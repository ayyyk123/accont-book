# 가계부 47.86차 — Firebase 서버 최신본 바로 불러오기

## 변경점
- 앱 실행/새 로그인 시 PC·모바일 기기의 이전 로컬 캐시 내용 및 이전 세션의 미동기화 표시를 최신 판단에 사용하지 않습니다.
- Firestore 서버 직접 읽기(get({source:"server"}))에 성공하면 **즉시 서버 최신 state를 적용**하고, 오래된 로컬 state로 Firebase를 업로드하지 않습니다.
- 서버 조회 실패/미로그인 시 오래된 로컬 캐시로 무조건 진행하지 않으며 재시도/로그인 안내를 보여줍니다.
- 서버의 state가 유효하되 구버전 앱이 남긴 해시 메타데이터가 다른 경우, 불필요하게 열기를 차단하지 않습니다. 이후 실제 저장은 서버 state와 초기 읽기 기준 해시 및 revision을 트랜잭션에서 확인한 후 수행합니다.
- 앱이 열린 **이후에 실제로 편집된 내용**에 대해서는 동시 수정 충돌 검사와 트랜잭션 병합을 유지합니다.
- 47.82~47.85 기능 유지, 앱 표시·서비스워커 캐시 47.86으로 통일.

## 적용
1. 이전 앱에서 Firebase `최신자료 저장` 완료가 확인된 후, 사용자 가계부 백업 JSON을 따로 보관합니다.
2. 이전 13개 파일을 모두 교체하고 PC·모바일에서 구버전을 종료한 다음 새 버전으로 접속합니다.
3. 저장된 Firebase 내용과 실제 화면이 맞는지 확인한 후 정상 사용합니다.

## 제한
- Firebase 서버 접속 자체가 실패하면 오프라인 캐시를 서버 최신본이라고 표시할 수 없습니다.
- Firebase 보안규칙을 바꾸지 않는 한 다른 구버전 앱의 서버 쓰기를 100% 원천 차단하지는 못합니다.
- 실제 계정의 네트워크 지연 시간을 자동으로 개선·보장하지는 못합니다.
