# 가계부 47.85차 — 실행 멈춤·버전 깜빡임 긴급 수정

## 해결한 문제
- 47.84차에서 새로운 Firebase 서버 검증 동기화 스크립트가 `flushCloud475` 등 아직 선언되지 않은 저장 함수를 먼저 읽어 JavaScript 오류를 일으키던 문제를 해결했습니다. 검증 스크립트 실행 위치를 모든 기존 기능 스크립트의 뒤로 이동하고, 최종 저장 경로를 다시 연결했습니다.
- 이전 버전 표시 타이머들이 서로 다른 차수를 표시하던 문제를 해결했습니다. 브라우저 탭·앱 내부 표시를 모두 47.85차로 맞췄습니다.
- 서비스워커 캐시 버전을 47.85차로 올려 새로운 앱 파일을 다시 캐시하도록 했습니다.
- Firebase 최신 데이터 조회가 지연될 때 8.5초 후 재확인·기기 JSON 백업 버튼을 표시하도록 했습니다. 서버에서 최신본을 확인하지 못하면 오래된 캐시를 최신이라고 표시하거나 자동 업로드하지 않습니다.
- 서버 데이터 검증 시 원본 상태를 해시한 이전 버전 기록도 수용하고, 저장 트랜잭션의 동일 리비전 비교에는 서버 원본 상태 해시를 사용하여 정규화 과정의 오탐을 줄였습니다.

## 유지한 기능
- 47.82차까지의 카드취소, 입금/환급 구분, 원본 거래 조회 및 삭제, 받을 돈 중복 방지, 고정이체 이번 달 취소 등 기존 기능 유지
- Firebase 서버 최신본 우선 조회, 서로 다른 항목의 변경 병합, 같은 항목 충돌 발생 시 자동 쓰기 차단

## 검증 및 적용
1. `index.html` 내 스크립트 문법검사 및 전체 13개 파일 압축 검증
2. 격리된 브라우저에서 **가짜 Firebase 데이터**로 로그인·최신 데이터 조회·로딩 화면 해제·버전 표시 확인 (실제 사용자 데이터에 접근하거나 쓰지 않음)
3. PC와 모바일의 실제 Firebase 계정 및 로딩시간 측정은 수행하지 못했습니다. 기존 47.84차에서 발생하던 무한 로딩 오류를 수정한 것이며, 캘린더와 같은 로딩 시간을 보장하지 않습니다.

**중요:** 업데이트 전 최신 가계부 전체 JSON 백업을 보관하고, 양 기기에서 옛 버전을 종료하세요. 과거 백업 JSON을 서버에 불러와 덮어쓰지 마세요. Firebase 서버 보안규칙 변경은 필요하지 않지만, 구버전 앱에서 직접 저장하는 것을 서버가 무조건 차단하는 것은 아닙니다.
